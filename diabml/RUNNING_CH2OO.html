1Set up the Mac

Once. PySCF and PyTorch both ship ready-built wheels for Apple silicon, so a plain virtual environment works; conda-forge (below) is faster for the scans.

zsh and comments. macOS's zsh does not treat # as a comment in typed commands, so a pasted line like pip install -e . # note passes # as an argument. The Copy buttons on this page leave comments out. To make pasted comments harmless everywhere: echo 'setopt interactivecomments' >> ~/.zshrc && source ~/.zshrc

# Homebrew Python 3.12 (skip if you already have 3.11 or newer)
brew install python@3.12

# get the code: diabml lives inside your MD_MLPES repository
cd ~/path/to/MD_MLPES && git pull
cd diabml

# one environment for everything in this guide
python3.12 -m venv ~/venvs/diabml
source ~/venvs/diabml/bin/activate
pip install --upgrade pip
pip install -e ".[qc,notebooks,test]"    # numpy scipy matplotlib torch + pyscf, jupyter, pytest

# check: 14 tests, under a minute
python -m pytest -q tests

# how many performance cores to give PySCF and PyTorch
sysctl -n hw.perflevel0.physicalcpu

CPU, not the GPU. diabml works in double precision, which Apple's GPU backend (MPS) does not support. That is fine: the networks are small, and the quantum chemistry is CPU work anyway. Set threads in each config to the performance-core count printed by the last command. 48 GB is far more memory than these calculations use; a cc-pVDZ CASSCF(8,6) point needs well under 1 GB.

Use conda-forge PySCF for the scans. The PySCF wheel that pip installs on macOS is built without OpenMP: it works (the tests pass, with an "OpenMP is not available" warning) but every calculation runs on one core. The conda-forge build is multithreaded. If you have conda, use it instead of the venv above:

conda create -n diabml -c conda-forge python=3.12 pyscf pytorch numpy scipy matplotlib ase pytest jupyterlab ipywidgets -y
conda activate diabml
cd ~/path/to/MD_MLPES/diabml
pip install -e . --no-deps          # register diabml; --no-deps keeps pip from installing its own torch
python -c "import pyscf, torch; from pyscf import lib; print(torch.__version__, lib.num_threads())"
python -m pytest -q tests           # 14 passed, no OpenMP warning

Take PyTorch from conda-forge too. A pip-installed torch carries its own OpenMP library; next to conda-forge PySCF the two collide and Python aborts on import torch ("Fatal Python error: Aborted"). If that happens: pip uninstall -y torch, then conda install -c conda-forge pytorch. Do not paper over it with KMP_DUPLICATE_LIB_OK=TRUE.

Activate the environment in every new terminal before running anything below (conda activate diabml). On an M5 Pro with 6 performance cores, set threads = 6 in each config: sed -i '' 's/threads = 8/threads = 6/' runs/02_nevpt2_2d/config.toml.

3The input file: config.toml

Every stage reads this file. Change a setting, rerun the stages after it; nothing else needs editing. This is the nevpt2_2d template as init writes it.

# Step 1: dynamic correlation. SA4-CASSCF(8,6) + SC-NEVPT2 with cc-pVDZ on the planar 2D grid (120 points).
[run]
name = "nevpt2_2d"
description = "SA4-CASSCF(8,6)/cc-pVDZ + SC-NEVPT2, planar (r_OO, angle COO)"
threads = 8                    # PySCF and PyTorch threads; use the number of performance cores

[refs]
source = "compute"
basis = "cc-pvdz"
ncas = 6                       # active space: C-O-O pi (3), O-O sigma/sigma*, terminal-O in-plane lone pair
nelecas = 8
nroots = 4                     # singlet A' states averaged with equal weights
spin = "singlet"
dynamic = "nevpt2"             # none | nevpt2 (state-specific SC-NEVPT2 on the SA-CASSCF orbitals)
energy = "nevpt2"              # which energies the models learn
max_cycle = 100

[refs.grid]                    # one list per coordinate; a single value holds that coordinate fixed
r_OO = [1.20, 1.275, 1.35, 1.425, 1.50, 1.60, 1.70, 1.80, 1.90, 2.00, 2.15, 2.30, 2.50, 2.75, 3.00, 3.50, 4.00, 5.00, 6.50, 8.00]
a_COO = [65.0, 85.0, 100.0, 117.7, 135.0, 155.0]
r_CO = [1.272]

[ladder]
compute = true                 # delta-CCSD(T) IE(CH2O) and EA(O); about 10-30 min
basis = "aug-cc-pvtz"
use = "experiment"             # experiment | computed: which ion-pair asymptote the frame uses

[frame]
zeta_env = 1.0                 # overlap envelope exponent (1/bohr): how fast learned corrections die off with r_OO
r_ref = 1.35                   # envelope = 1 at this O-O distance (Angstrom)
feature_zetas = [0.6, 1.0, 1.6]

[train]
models = ["framed", "cdnn"]    # framed = ChannelFrame + small networks; cdnn = plain CDNN (Shu et al. 2025)
exclude_flagged = true         # skip unconverged points and points whose active space changed character
hidden_framed = [128, 64]
hidden_cdnn = [128, 64]
coupling_init = 0.1            # eV; framed couplings must not start at exactly 0 (their energy gradient vanishes there)
lr_framed = 2e-3
lr_cdnn = 1e-3
alpha2 = 1e-6                  # L2 weight penalty (eq. 5 of the CDNN paper)
epochs = 6000
restarts = 2
seeds = [0, 1, 2]

[train.random_split]           # interpolation test: random train / validation / test split of all usable points
enabled = true
train_fraction = 0.75
val_fraction = 0.125

[train.extrapolation]          # train only on r_OO <= r_train_max, test beyond it
enabled = true
r_train_max = 2.3

[train.learning_curve]         # test error vs number of training points (fixed test set)
enabled = true
n_train = [20, 40, 60, 90]
test_fraction = 0.2

[train.restraint]              # diabatic restraint: ground-state weight of the ionic structure follows the CASSCF charge
enabled = false
weights = [0.0, 0.1, 1.0, 10.0]
q_ref = -0.6                   # terminal-O Mulliken charge taken to mean "fully zwitterionic" (an assumption: vary it)
min_gap_eV = 0.1               # apply only where S1 - S0 exceeds this (eigenvector derivatives blow up at degeneracies)

4The runs, in order

Each run answers one question and feeds the next. Every stage can also be run on its own: refs, ladder, train, figures, tables, report; all runs them in that order. Times below come from test runs on a 2-core cloud machine (about 5 s per geometry for 6-31G* CASSCF + NEVPT2, about 30 s to train one model for 6000 epochs; a full training stage fits about 50 models); your M5 Pro should be faster, and status reports the real rate as a scan runs.

01_baseline

Reproduce the talk's CH₂OO results

no quantum chemistryabout 25 min of training on 2 cores

Do the framed model's advantages hold up across seeds and training-set sizes?

python -m diabml.workflow.ch2oo init runs/01_baseline --template baseline
python -m diabml.workflow.ch2oo all  runs/01_baseline

Check: in T3 (example below) both models fit inside the data to about 1–2 kcal/mol for S₀–S₂; trained only on r ≤ 2.3 Å, the framed model stays within 1–3 kcal/mol beyond it while plain CDNN is off by 100–330. F6 shows why. These numbers are better than the talk's because the workflow fixes how the couplings start (coupling_init, section 3). Also check F10 for holes below the data. This run is the yardstick for everything after it.

02_nevpt2_2d

PySCF scan · 120 geometriesΔCCSD(T) ladderroughly 15–45 min of scan

How much does dynamic correlation change the binding and the state ordering, and does the frame still hold?

python -m diabml.workflow.ch2oo tables  runs/02_nevpt2_2d
python -m diabml.workflow.ch2oo report  runs/02_nevpt2_2d

SA4-CASSCF(8,6)/cc-pVDZ with orbitals carried from the nearest finished geometry, then SC-NEVPT2 for each of the four roots. Both levels are stored; the models learn NEVPT2. The ladder stage computes IE(CH₂O) and EA(O) by ΔCCSD(T)/aug-cc-pVTZ and records them next to experiment.

Check: T1 (all points converged, consistent active space, O(¹D) components within a few meV at 8 Å), F4 and T6 (the NEVPT2 shift; in a 6-31G* test along the equilibrium cut it deepened the S₀ well from 1.2 to 2.3 eV), and F1/F4 for kinks where states approach. The 6-31G* test already shows some in S₂ and S₃ near 1.8–1.9 Å (sample F4 below); decide whether training on NEVPT2 is safe there.

03_cas_3d

Add the C–O stretch

PySCF scan · 480 geometriesroughly 1–3 h of scan

The zwitterion (H₂C=O⁺–O⁻) and the biradical (H₂C•–O–O•) prefer different C–O lengths. Does a third coordinate change which structure carries the ground state, and does the frame's advantage survive in 3D?

python -m diabml.workflow.ch2oo init runs/03_cas_3d --template cas_3d
caffeinate -i python -m diabml.workflow.ch2oo all runs/03_cas_3d

r(C–O1) ∈ {1.20, 1.272, 1.35, 1.45} Å on top of the 2D grid. The frame's asymptotes now follow r(C–O), interpolated from the 8 Å points, because the CH₂O fragment energy depends on it. Look at F3b and at the learning curve (F8, T4): with three coordinates, data efficiency is what the frame is for.

04_restraint

Make the learned matrix more diabatic

uses run 02's referencesabout 30 min of training on 2 cores

Energies alone leave the structures unmixed. If the ground state's weight on the CH₂O⁺ + O⁻ structure is tied to the computed terminal-O charge, how much energy accuracy does that cost?

python -m diabml.workflow.ch2oo init runs/04_restraint --template restraint
python -m diabml.workflow.ch2oo all  runs/04_restraint     # refs copies ../02_nevpt2_2d/data/refs.npz

The restraint adds weight × (ionic population of S₀ − q / qref)² to the loss, only where S₁ − S₀ > 0.1 eV. Check: F9 and T5 for the trade-off, then rerun with q_ref = −0.5 and −0.8: the answer should not hinge on that choice.

5Long scans

  • Keep the Mac awake. Prefix the command with caffeinate -i. For a run you will leave, start it in the background and close the terminal: nohup caffeinate -i python -m diabml.workflow.ch2oo refs runs/03_cas_3d > runs/03_cas_3d/logs/nohup.out 2>&1 &
  • Watch it. python -m diabml.workflow.ch2oo status runs/03_cas_3d prints points done, seconds per point, time left and unconverged points. tail -f runs/03_cas_3d/logs/refs.log shows the stream.
  • Stop and resume. The scan writes data/scan_checkpoint.npz after every geometry, orbitals included. Rerun the same refs command and it continues from where it stopped, starting each new point from its nearest finished neighbour's orbitals.
  • Change the grid, start fresh. A checkpoint is only reused for exactly the same points. To redo a finished scan, use refs --force.
  • One scan at a time. Points are visited along a nearest-neighbour path for orbital continuity, so a scan is serial; speed comes from threads. Two different runs can go in parallel if you split the cores between them.

8Troubleshooting

SymptomWhat to do
Red crosses in F1; T1 shows unconverged pointsTraining skips them (exclude_flagged = true). If there are many, raise max_cycle and rerun refs --force, or add intermediate r(O–O) values so neighbouring orbitals are closer.
"consistent active space" below the point countThe active orbitals changed symmetry character at some points (often at very short or bent geometries). Inspect those points in F1; trim the grid there or widen the active space.
Kinks in NEVPT2 curves where states approachA limitation of state-specific NEVPT2 near near-degeneracies. Compare with the CASSCF curves in F4; train on energy = "casscf" for that region, or move to a multistate method (see 9).
pip install fails building PySCFYour Python is not arm64 or is older than 3.11. Check with python -c "import platform; print(platform.machine())" (should print arm64) or use the conda route in 1.
Scan much slower than expectedCheck threads and that nothing else is using the cores. status shows seconds per point after the first few.
"checkpoint belongs to a different grid"The grid in config.toml changed since the scan started; it starts fresh. Put the old grid back to resume.

9After these runs

  • Out of plane. The H–C–O–O torsion and out-of-plane O motion break Cs, so A′ and A″ states mix: drop the symmetry, double the roots, and give the frame the A″ components of O(¹D).
  • Triplets. spin = "triplet" already works in the scan; a triplet frame (CH₂O + O(³P) channels) still needs writing.
  • Multistate dynamic correlation. XMS-CASPT2 or MRCI (OpenMolcas, Molpro, ORCA) for the final surface; import energies into a RefSet and use refs.source = "file".
  • The dioxirane channel. Ring closure is the main unimolecular route of CH₂OO. The grid reaches ∠C–O–O = 65°; the region near dioxirane needs its own points.
  • Dynamics. See section 10.

10From surface to dynamics

The runs above end with a good reduced-dimensional surface: a function of r(O–O), ∠C–O–O and r(C–O) for a planar molecule with a rigid CH₂O frame. Molecular dynamics needs energies and forces in all 9 internal degrees of freedom of CH₂OO. The pieces that carry over unchanged are the structures in the matrix, how their asymptotes are fixed, the walls, and the way the networks enter. This section describes what you can do now and the steps to a full-dimensional surface.

How a trained model is stored

Every model the workflow keeps is written as two files in models/:

FileContents
random_framed.ptA PyTorch file holding a dictionary with two entries. state_dict contains the weights and biases of every layer, as tensors. spec is plain data that says how to rebuild the model: class, layer sizes, input scaling, and for a framed model its five structures with their asymptotes, charges and walls, the asymptote table, and the starting couplings. meta records the coordinates and their units, the energy zero and unit, the electronic-structure method, the experiment and the training-set size.
random_framed.jsonThe same spec and meta as readable text, plus every parameter's shape and the parameter count. Open it to see exactly what a model is.

Load a model with load_model. It rebuilds the model from the spec and fills in the weights. The file contains no pickled code, so it opens with PyTorch's safe loader and keeps working when unrelated code in the package changes. To share or archive a surface, the .pt file alone is enough.

from diabml.models import load_model
model = load_model("runs/01_baseline/models/random_framed.pt")
model.meta["coord_names"]                # ['r_OO', 'a_COO']
model.predict([[1.35, 117.7]])           # S0..S3 in eV
model.matrix([[1.35, 117.7]])            # the 5 x 5 matrix: three O(1D) structures, biradical, ion pair

The ASE calculator

diabml.dynamics turns any saved model into an ASE calculator. A surface maps Cartesian positions to the model's matrix through differentiable coordinates. The calculator then diagonalises the matrix and uses automatic differentiation to return, for every state, the energy Ek, the forces Fk = −vkᵀ(∂Ω/∂R)vk, and the couplings between states. Forces agree with finite differences to 10⁻⁸ eV/Å.

from diabml.models import load_model
from diabml.dynamics import CoordinateSurface, DiabmlCalculator, ch2oo_atoms, ch2oo_coordinates, reduced_restraints

model = load_model("runs/01_baseline/models/random_framed.pt")
names = model.meta["coord_names"]
atoms = ch2oo_atoms(r_oo=1.35)                                   # ase.Atoms, order C O1 O2 H H
surface = reduced_restraints(CoordinateSurface(model, ch2oo_coordinates(names)), atoms.positions, free=names)
atoms.calc = DiabmlCalculator(surface, state=0)

atoms.get_potential_energy(), atoms.get_forces()                 # active state: eV, eV/Å
r = atoms.calc.results
r["energies"], r["all_forces"], r["couplings"], r["structure_weights"]
atoms.calc.state = 1                                             # switch state, e.g. after a hop
ResultShapeMeaning
energy, forcesscalar; (5, 3)the active state, which is what ASE integrators use
energies(4,)S₀–S₃, eV
all_forces(4, 5, 3)forces on every state, eV/Å
couplings(4, 4, 5, 3)derivative couplings dkl = vkᵀ(∂Ω/∂R)vl / (El − Ek), 1/Å

Couplings and the matrix. Unless the matrix is restrained toward diabatic (run 04), dkl describes this particular matrix rather than the molecule. Methods that need only energies and forces, such as curvature-driven surface hopping, are safe with any trained model. Tully-style surface hopping should wait for a restrained matrix.

A test trajectory you can run now

A reduced model gives forces only along its own coordinates. reduced_restraints therefore holds the rest (a planar CH₂O frame, plus r(C–O) for a 2D model) with stiff springs. Their energy is added equally to every state, so energy is still conserved. ASE's FixInternals constraints do not conserve energy here; tests showed drifts of hundreds of meV, which would hide real problems with the surface.

python examples/ch2oo_nve.py runs/01_baseline/models/random_framed.pt --temperature 1500 --steps 4000 --dt 0.2 --out runs/01_baseline/nve_1500K

The script writes a CSV (time, all four energies, r(O–O), angle, ionic weight) and an ASE .traj file you can open with ase gui, then prints the total-energy drift. On the baseline model, 4000 steps of 0.2 fs at 1500 K kept the total energy constant to 0.11 meV rms (0.08 meV drift) while the kinetic energy swung by 123 meV. At 4000 K the molecule dissociated out to r(O–O) = 11 Å with 0.37 meV rms, and S₁ − S₀ fell to 5 meV, the degenerate O(¹D) components. Running only on S₀ stops being meaningful exactly there. Halving the time step should cut the fluctuation about fourfold; if it does not, the surface has a kink.

Steps to a full-dimensional surface

  1. Full-dimensional inputs. Feed the model all 10 interatomic distances (DistanceSurface). Average over swapping the two H atoms (permutations=[[0,1,2,3,4],[0,1,2,4,3]]), which makes energies and forces exactly invariant. Keep the five structures and the r(O–O) envelope. The asymptotes then need surfaces for the fragments: CH₂O in its ground state, its T₁ state and its cation. This is the electron ladder used as fragment surfaces rather than single numbers; the r(C–O) table in run 03 is the first step.
  2. Reference data where trajectories go. Start from your MD_MLPES normal-mode and hot-MD geometries, recomputed with SA-CASSCF and NEVPT2. Without the planar restriction A′ and A″ states mix, so use more roots (about 6–8) and track which state is which.
  3. Forces in training. PySCF has analytic SA-CASSCF gradients for each state (mc.Gradients().kernel(state=i)), giving 15 force components per geometry. Training on forces as well as energies makes the data go much further. PySCF has no NEVPT2 gradients, so learn CASSCF energies and forces plus a smooth NEVPT2 − CASSCF energy correction.
  4. Active learning. Train several models with different seeds and run short trajectories with the calculator. Compute new references where the models disagree most, retrain, and repeat. This puts data in the middle zone rather than at equilibrium.
  5. Validate before production. Check the stationary points: the minimum, the O–O dissociation path and dioxirane. Check harmonic frequencies against the reference (no modes above 5000 cm⁻¹, no spurious imaginary ones), F10 and its full-dimensional equivalent (no holes), and energy conservation over picoseconds.
  6. Choose the dynamics.

  7. Initial conditions and observables. For chemically activated CH₂OO, sample microcanonically at the energy left from ozonolysis and measure lifetimes and the branching between dioxirane and CH₂O + O, compared with RRKM and master-equation rates. For photodissociation, use Wigner sampling with excitation into the UV band and measure O(¹D)/O(³P) yields and kinetic-energy release, compared with Lester's experiments. For hot-molecule IR, the model's structure weights give a starting point for a dipole surface.
