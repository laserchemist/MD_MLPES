diabml workflow guide

Quasi-diabatic machine-learned potential energy surfaces for CH2OO: how each kind of run is set up and carried out, where its results go, and where the trained models live. Every command runs from the diabml folder: ~/Documents/Research/MD_MLPES/diabml.

Overall workflow

A study is a series of run folders under runs/. Each run reads its settings from RUN/config.toml and the files earlier stages wrote, so stages can be rerun one at a time. Data flow forward from one run to the next through refs.file: a new run starts from another run's data/refs.npz.

Rule of thumb. Never change a finished run's data in place: make a new run folder that points at it with --refs. Each folder then records exactly what was done (its config.toml and logs/).

Explore: active learning from dynamics

explore RUN [--force] trains the committee, then runs watched constant-energy trajectories on its average from every start in [explore] (r_OO 1.35/1.6/1.9 Å × 1000/1500/2000 K = 9 trajectories, 300 fs each). Each stops before the surface goes wrong:

Stop reasonSettingWhat it means
spreadspread_eV = 0.25committee members disagree on the active state: not enough data here
distancedata_distance = 1.5more than 1.5 grid steps from every reference point
jumpjump_meV = 5total energy changes in one step: a kink or break in the surface
forceforce_max = 25extreme force (a steep wall or a hole). Raise to 40 if stops are at the real inner O–O wall
completedsteps × dtran to the end on trusted surface

The stopping geometries (plus a few fs of look-ahead) become data/proposed.npz for compute. Nonadiabatic regions (small gaps, Massey parameter) are logged, not stopped on. Output: dynamics.html, results/explore.json, results/trajectories/traj_NN.{traj,npz}, models/committee_k.pt. The loop has converged when every trajectory completes; then try hotter or more stretched starts.

Keep data/audit/. The orbital library of every later round points at the .gbw files there. The .densities files (most of its 1.3 GB) are not needed and can be deleted.

Production surface

production RUN works on any run with data/refs.npz. Test phase: 10 % of the usable points held out, 5 framed members (charge restraint + coupling fit) trained on the rest, errors reported by region (dynamics / high energy / corner). Final phase: the 5 members retrained on everything and saved as one averaged ensemble. Then hole scans: below the shortest O–O distance and beyond the data in r_CO (worst member and the ensemble mean, which is what dynamics feels). About 35 min.

Writes models/production.pt (+ .json), results/production.json, results/production_test.npz, P1 (parity), P2 (cuts), P3 (hole scan), table T10.

Recipes

Next exploration round (the main loop)

# 1. new folder that starts from the previous round's data
python -m diabml.workflow.ch2oo init runs/20_md7 --template explore --refs ../19_md6_sc/data/refs.npz
#    optional: edit runs/20_md7/config.toml  ([explore] force_max = 40.0, [active] epochs = 8000)

# 2. everything: refs, ladder, explore, compute (ORCA), merge, tables, report
caffeinate -i python -m diabml.workflow.ch2oo all runs/20_md7

#    or stage by stage
python -m diabml.workflow.ch2oo refs    runs/20_md7
python -m diabml.workflow.ch2oo explore runs/20_md7      # look at runs/20_md7/dynamics.html
python -m diabml.workflow.ch2oo compute runs/20_md7      # ORCA at the stopping geometries
python -m diabml.workflow.ch2oo merge   runs/20_md7      # → runs/20_md7/data/refs.npz

# 3. next round: runs/21_md8 with --refs ../20_md7/data/refs.npz

Watch per round: trajectories completed (explore log, dynamics.html), the committee error at the new points before training on them (compute log, A2), and how many points had several SA-CASSCF solutions (compute_orca.csv).

The dynamics is Born–Oppenheimer on one adiabatic state; the HTML log marks nonadiabatic regions. examples/ase_quickstart.py MODEL shows a single point, a geometry optimisation and a short S1 trajectory with the same calculator.
